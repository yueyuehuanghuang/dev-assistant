# 固定任务评测

在项目根目录运行 `python evaluate.py` 或 `python evaluate.py --live`。

- **回放模式**：模型输出和工具返回都固定，用于复现 Agent 回路和验证评分器，不衡量模型质量。
- **真实模型模式**：使用 `.env` 中的模型，对固定英文任务自主选择工具；GitHub 工具仍使用固定合成结果，不请求真实仓库。会产生 API 费用，不写入聊天数据库。

8 个任务分别覆盖无需工具、澄清仓库、概览、源码、Issue、PR、工具失败、提示注入样例。
每个任务独立会话。报告保留观察到的工具及参数、最终回答、评分和异常类型，不记录 API 密钥。

评分规则：

1. 工具调用名称及经过业务参数模型补齐默认值后的参数完整匹配，按调用次数计算 precision/recall；省略 `page` 与显式 `page=1` 等价，多余调用计为失败。仍可能存在合理的替代工具路径，应查看报告人工复核。
2. 结果包含预设答案关键词（忽略大小写）。这不证明回答语义正确。
3. 必要来源必须出现在回答中，并精确对应实际成功工具结果中的结构化 URL；额外 GitHub 链接也须有工具证据。同一 commit 文件引用可以缩小到实际读取范围内的行号，不允许引用未读行。当前不检查其他域名引用或每个结论与证据的对应关系。
4. 一个任务必须全部规则通过才算通过；总结果有失败时进程退出码为 1。

增加任务时在 `cases.json` 填写 prompt、tools（名称、参数、结构化结果）、replay_answer、answer_terms、required_urls。
不要用真实密钥、私人会话或私有源码作为 fixture。先用回放验证评分器，再比较固定模型和提示词版本的 live 结果。
报告写入 `output/`，默认不纳入版本控制。当前报告为 JSON，未提供可视化评测面板或 LLM-as-judge。

只修改评分逻辑、未改 fixture 时，可运行 `python evaluate.py --rescore output/eval-live.json`，使用记录中的原始工具调用和最终回答重新评分，不调用模型，输出 `output/eval-rescored.json` 并注明原报告路径。修改任务或工具样例后应重新运行 live，而不是重评分。
